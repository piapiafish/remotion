# P1-01 人工编辑器审查报告

日期：2026-11-01（北京时间）。审查结论：**已完成本轮审查，发现待修复问题；阶段一产品尚未验收。**

## 范围与执行环境

权威项目为 D 盘 MultiAgent-3D-Promo-Studio。当前会话对 D 盘只读，本轮复制当前源码、配置、模型和素材，在允许写入的临时目录执行；193 份文件的 SHA-256 在复制时一致，结束后再次核对原目录，未发现变化。[文件基线](source-baseline.json)、[结束核对](source-integrity.json)。

Windows 11 10.0.26200，Node 24.22.2，npm 11.19.1，项目 Python 3.10.6，Playwright 1.58.0，Chrome 156.0.8078.76，FFmpeg/FFprobe 9.0.2。浏览器以 headless 方式执行真实界面、文件输入、下载及 WebGL 渲染。

Python Playwright 在驱动初始化阶段超时，随后改用同一安装内的 JavaScript SDK，浏览器成功启动。本地 TCP 连接被沙箱拒绝，因此浏览器通过 Playwright 路由从磁盘提供原封不动的 Vite 构建产物，使用 localhost 安全上下文。该方法验证前端编辑器行为，不构成 Vite 启动或 studio API 网络通过证明。两种运行方式和异常都保留在 [diagnostics](diagnostics/)。

## 已实际走通的能力

- 编辑器启动；添加、复制、删除设备；普通参数修改只影响当前选中设备。
- 播放头点击与拖动定位。本轮的关键帧拖动检查单独记录。
- iPhone 17 Pro 导入真实录屏，第二台 Google Pixel 9 Pro XL 导入独立截图。
- 两台设备、不同素材和旋转轨道写入 .mockup；在全新、无原 OPFS/IndexedDB 数据的浏览器上下文中重开。工程 JSON 完全一致，两个媒体文件的字节哈希一致，恢复后的轨道可定位到 180°。
- 取消导出后可以继续修改，取消没有产生视频下载。
- 单台 iPhone 17 Pro 与真实录屏导出 H.264 MP4：1920×1080、30 FPS、2 秒、60 帧。[测试视频](browser/P1-01-1080p30.mp4)、[导出工程](browser/06-export-project.mockup)、[FFprobe](browser/06-ffprobe.json)。
- 模拟 VideoEncoder 缺失时，界面给出提示并可导出 PNG 序列；实际下载了 320×180、15 帧的序列。这项小尺寸回退检查与主 MP4 的 1080P 检查分别记录。

保存恢复样本：[双设备工程](browser/04-media-project.mockup)、[新上下文重存版本](browser/05-reopened-project.mockup)。

视频第 0、30、59 帧经 FFmpeg 解码，与同帧号、同工程、同画质的引擎帧比较，SSIM 分别为 0.993109、0.995747、0.994146。该数值支持渲染／素材时序一致性，不代表用户的最终视觉质量认可。
