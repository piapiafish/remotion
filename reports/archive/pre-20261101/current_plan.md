## 1. 项目目标与工作原则

最终希望完成：用户导入软件源码 → AI 分析功能 → 推荐视频方案并与用户协商 → 给出录屏指导 → 用户上传录屏 → 生成 3D 宣传镜头 → 合成完整视频。

- 当前优先保证能运行、能导出、稳定且容易使用，前端保持简洁。
- 继续复用原 Three.js / React Three Fiber、真实 GLB、视频贴图、时间轴、导出器与 Remotion 合成链路。
- 不为推进功能重做整套 UI，也不另建一套与原时间轴并行的关键帧系统。
- 规划、代码已存在、实际运行通过、用户电脑验证通过，必须分别记录。

## 3. 当前实际使用流程

在包含 package.json 的项目根目录启动：

    npm.cmd run dev

打开终端显示的本地网址，右侧顶部“AI 导演 · 手机运动计划”默认展开：

1. 选择手机，点击“生成运动计划并应用”；当前明确使用模拟 AI，固定生成 15 秒入场、旋转与悬停示例。
2. 自动切到 Movie，运动已应用到左侧主画布；点击播放、轨道关键帧或逐秒画面预览。
3. 有外部 AI 的手机运动 JSON 时，展开下面的导入入口，粘贴或选择本地文件自动应用。
4. 保存 .mockup 保留画布运动和说明，也可以下载原始运动 JSON。

运动要求暂时不接在线 AI、不解析任意自然语言；可执行输入是 phone-motion/1 JSON 中的时间、位置、旋转角度、缩放和说明。完整格式与示例见 [手机运动计划](docs/PHONE_MOTION_PLAN.md)。

原素材分镜和成片渲染保留在最后的“旧版素材分镜与成片渲染”：

1. 粘贴外部 AI 返回的分镜 JSON，点击“导入并自动保存”；或选择 JSON 文件自动导入。
2. 检查镜头数、时长、画幅与运动；没有外部方案时可使用“生成离线方案”。
3. 点击“生成已保存方案的视频”，等待逐镜头渲染与整片合成。
4. 完成后在面板播放、跳转和下载 final.mp4。

自然语言提示词本身不能直接执行，外部 AI 需要返回符合本项目 Video DSL 的分镜。个人录屏目前仍需先放入项目目录，并在分镜中填写相对路径，例如 assets/my-recording.mp4。

| 内容 | 保存位置或方式 |
| --- | --- |
| 自动保存的分镜 | work/studio/<方案编号>/storyboard.json |
| 自动渲染结果、报告和日志 | output/studio/<方案编号>/ |
| 最终视频 | output/studio/<方案编号>/final.mp4 |
| 原可视化编辑器工程 | 手动保存为 .mockup，继续使用原保存与恢复机制。 |

旧版成片本地接口随 Vite 开发服务启动，仅支持本机访问；静态托管页面和 npm run preview 不提供这套磁盘保存、进程和渲染能力。新的手机运动 JSON 在浏览器内应用到画布，不依赖该接口；原生轨道与说明可随 .mockup 保存。画布的手动修改不反写原始运动 JSON，旧版成片分镜也尚未与画布完整双向同步。
