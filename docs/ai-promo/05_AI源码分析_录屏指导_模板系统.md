# AI 源码理解、分段、录屏指导、模板收藏

## 1. 分段工作流

输入软件源码 ZIP/项目文件夹（未来 GitHub），只读扫描技术栈、页面、路由、组件交互和能被用户感知的功能，生成可编辑功能清单；用户确认后，按展示价值生成 N 个独立片段。每个片段包含 `featureId`、展示目标、说明文案、推荐模板、录屏指南、建议长度、可编辑镜头状态、素材引用。

**不要固定三镜头，也不要按源文件数量机械生成片段。** 类似“智能分析→结果看板”这种连贯功能可以合并成一个片段。必要时允许用户拆分。

## 2. 证据与安全

- 功能项记录可溯源到的相对文件路径、组件、路由或函数名，并区别 `located / inferred / user-confirmed`。
- 源码识别不到的页面按钮不得编造：应提醒用户补充页面截图或标注“需要实际验证”。
- 默认跳过 `.env`、密钥、缓存、依赖目录、构建产物；限制 ZIP 解包路径/大小；未知仓库代码不自动执行。
- 用户的私有源码、录屏、日志和产品操作记录不要无授权传送给第三方。云端 LLM 调用前有清楚的数据范围说明。

## 3. 录屏指导结构

```json
{
  "featureId": "task-create",
  "title": "快速创建任务",
  "goal": "展示创建操作简洁且结果可见",
  "preparation": ["打开任务列表", "准备非真实的测试任务名称", "隐藏账号与敏感数据"],
  "steps": [
    {"action":"等待列表加载完成", "holdSeconds":1},
    {"action":"打开新建任务入口", "evidence":"用户确认的任务列表页面"},
    {"action":"填写测试标题并提交"},
    {"action":"展示创建成功结果", "holdSeconds":2}
  ],
  "recordingSecondsSuggested": [10,15],
  "editedSegmentSecondsSuggested": [8,12],
  "screenOrientation": "portrait",
  "notes": ["尽量避免光标快速乱晃", "必要时等待加载动画结束"]
}
```

上例是**概念示例而非对实际项目源码的分析结论**，真实项目中每一步必须在 UI 或代码中有依据。

上传录屏后可先做硬件/媒体检查：是否可解码、尺寸比例、时长、是否可能需要裁剪、录屏画面能否正确映射 GLB 屏幕。更强的视频视觉审核可以后置。

## 4. 片段和模板的分离

- `Segment` 是某个项目独有的编辑结果：模板快照、录屏引用、变更过的字幕与镜头关键帧。
- `Template` 是可复用的镜头配置：布局/动画/字体/占位视频、安全区等，不应含具体用户录屏。
- `Favorite` 是用户与 `Template` 的关联，不改变模板内容。
- `MyTemplate` 是用户把当前片段镜头配置另存的一份可复用快照。
- `Composition` 负责整片排序、转场、音频与输出比例，不应反向修改片段基础数据。

## 5. AI 推荐的边界

推荐系统结合功能类型、需要展示的内容密度、设备比例、用户收藏和常用风格。收藏模板可以提高优先级，但不能覆盖功能可读性等关键条件。初期可以采用轻量规则 + 单次模型筛选，不需要复杂推荐学习系统。

## 6. 自然语言修改

例如“手机从画面左下侧进入、边上升边旋转，中央停 2 秒，再向右上退出”，应首先更新特定片段的 `VisualIntent`/关键阶段，再重新编译局部轨道；保留录屏、已有文案和其他设备配置。所有变更可撤销，用户可在专业模式继续修改。
