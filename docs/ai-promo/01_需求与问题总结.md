# 项目定位与核心问题（会话总结）

## 用户确认的真正目标

项目从“文字输入后一键生成固定三镜头宣传片”转向**AI 阅读代码、分段生成可编辑视频模板、录屏指导、用户微调、跨项目复用与最终合成**。

建议用户旅程：

```text
导入源码 → AI 扫描页面/路由/交互与功能 → 用户确认功能清单
  → AI 生成若干独立视频片段 → 片段列表 → 打开片段详情
  → 阅读可操作的录屏指导 → 用户录屏/上传 → 3D GLB 设备贴屏
  → 选择系统模板/收藏模板/自定义模板 → 简洁编辑
  → 按需精细关键帧与 AI 自然语言微调 → 保存或独立渲染
  → 成片页面排序、添加配音/字幕/音乐/转场 → Remotion 输出 MP4
```

## 核心问题与对应解决策略

| 问题 | 根本原因 | 解决策略 | 先验收什么 |
|---|---|---|---|
| 剪辑页面密集、眼花缭乱 | 把模板、指南、片段列表、高级参数塞到一起 | Dify 风格分页面；单片段编辑仅四个主要操作；专业模式折叠 | 4 页面能导航，编辑器主界面不出现冗杂参数 |
| 通用模型多模态较弱 | 要模型同时承担语义理解、坐标计算、设计每帧、审美判断 | 模型输出构图意图和少数关键姿态；求解器做投影与位置；视觉反馈按需调用 | 无多模态也能产出稳定单/双机画面 |
| 设备大小、位置不合理 | Three.js 世界坐标不是屏幕坐标，模型与相机比例各异 | 归一化画面目标坐标 + 实测包围盒投影 + 坐标求解 | 设备组中心和占比可控 |
| 多设备间距发散 | 各设备独立猜绝对坐标和曲线 | 组合父节点运动 + 局部相对位姿；对动态展开/错层另设局部轨道 | 2–5 设备排列、进出画不无故拉散 |
| 固定模板限制创造性 | 只允许选固定位置和固定动画 | 模板是可编辑初稿；参数连续可调；允许 AI 新增关键帧与布局阶段 | 有模板之外的新轨迹且可再次编辑 |
| 模型可能离开画面 | 把“越界”一律视为错误 | 按 `entrance/transition/hero/exit` 区分软约束；自由进出画面 | 入场/退场不被算法拉回 |
| 文案遮挡、画面没重点 | 未考虑文字安全区及相机投影 | 构图区域与文字区域分别计算；在稳定展示阶段采样屏幕投影，必要时微调 | 标题与关键设备屏幕互不遮挡 |
| 跨项目重复设计 | 没有收藏、个人模板和版本 | 模板库、持久化收藏、个人模板、素材引用与配置分离 | 同一模板用于第二个项目不带原录屏 |
| 项目基础能力未经联调 | 有代码但缺少真实生成演示证据 | P0 真实运行验证：原工程→GLB→贴屏→关键帧→分段导出→Remotion | 有播放正常的真实 MP4 和测试记录 |

## 从两段视频归纳的设计目标

- 视频 A《织界》：双手机 + 右侧文案、手机/平板组合 + 左侧文案、横屏设备 + 右侧文案。**强调镜头留白、动态组关系和不同形态设备的比例**。
- 视频 B《多手机功能演示》：开头多手机展开、三手机前后层叠、不同功能长时间稳定演示。**强调多设备组布局、功能分段和适时停留**。
- 系统应该懂得：**开头和过渡可动得大；真正的功能操作镜头需要易读且稳定。**

## 产品边界

- AI 设计视频的**意图、片段结构和部分关键帧**，而不是每一帧坐标。
- 用户可以直接拖动设备或修改首尾关键帧；模型允许有意出画。
- Three.js/R3F 负责 3D 单镜头、贴屏及时间轴，Remotion 负责整片拼接、字幕动画、配乐和转场。
- 对模型的唯一硬门槛是数据合法与运行安全；构图规范大多采用**可覆盖的建议**，避免重演过度规则化问题。
