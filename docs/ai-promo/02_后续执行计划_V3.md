# 后续执行计划 V3｜源码理解 × 分段视频 × 智能构图 × 简洁编辑

> **本计划替换先前“固定三镜头一键成片”为优先目标的旧路线。** 以前开发的 Video DSL、Agent、Playwright、Remotion 可以按实际可用性复用；不要直接删除或推倒重写。以本仓库真实代码为准，而不是凭讨论中提及的功能名称判断已完成。

## 总体架构

```text
源码导入/解析（只读、安全）
        ↓
Feature Catalog（带代码证据、可人工确认）
        ↓
Segment Planner（N 个独立片段 + 录屏指导 + 模板候选）
        ↓
工作台/片段列表/录屏指导/独立片段编辑器/收藏中心
        ↓
Visual Intent / Layout Plan（0–1 画面构图 + 入场/展示/退场意图）
        ↓
Composition Engine（设备组布局、实测投影、组内相对位姿、预览反馈）
        ↓
原 Three.js/R3F GLB + VideoTexture + SampleTimeline
        ↓
独立镜头 MP4/PNG Sequence
        ↓
Remotion（整片剪辑、字幕/音频/转场）→ MP4
```

## 非目标与复杂度控制

- MVP 不要求完全自动录屏、不要求多 Agent 共识投票、不要求 LLM 自由生成 Shader、不要求自动生成未知 3D 模型。
- 不重写 `src/scene/GltfDevice.tsx`、`src/timeline/sample.ts` 等成熟底层，除非有明确缺陷证据。
- 不创建平行于原时间轴的第二套关键帧真相来源；布局求解**编译为现有 TrackSet**。
- 不在用户未要求时强制自动调平、拉回出画设备，不追求每一帧都完美居中。

## P0｜现有工程可运行性与端到端技术核验（必须先做）

**目标**：明确“已经有代码”与“真实成片成功”之间的差距。

**任务**：

1. 安装依赖（有网络的 Node 环境），执行 `npm ci`、`npm test`、`npm run build`；如果当前工程另有子项目依赖，分别按 README 检查。
2. 启动 Three.js 编辑器，逐一验证 4 个真实 GLB 模型；保留 GLB 文件、授权与归属文件。
3. 上传真实 MP4，将画面映射到模型屏幕并检查 UV、比例、画面方向和遮挡。
4. 设置起止关键帧以及旋转 / 缩放，确认相同时刻多次渲染一致。
5. 渲染一个 5–10 秒独立片段；针对旧的扩展分支，进一步验证 Playwright 自动导出和 Remotion 合成。
6. 将成功的 MP4、渲染日志、失败用例保存到 `output/` 或测试报告中。

**验收**：至少一个高质量真实设备的贴屏、关键帧视频导出成功；录屏与关键帧同步；明确记录 Remotion 是否真实生成成片。否则不冒称通过。

**文件重点**：`src/devices/manifest.ts`、`src/scene/GltfDevice.tsx`、`src/media/screenVideo.ts`、`src/timeline/`、`src/export/`；扩展分支额外看 `src/automation/`、`services/render-worker/`、`remotion-compositor/`。

## P1｜构图引擎最小闭环：单设备

**目标**：从画面意图自动求出合适的 3D 位姿，而不是让 AI 猜世界坐标。

**实现任务**：

1. 在独立的 `src/composition/`（建议路径，可根据现有架构调整）定义布局意图 DSL：`anchor`, `targetCoverage`, `textRegion`, `phase`, `cameraPreference`, `allowOffscreen`。
2. 用真实设备运行时世界变换和相机，把设备 3D 包围盒投影成 0–1 屏幕矩形；处理近裁面、相机后方和旋转造成的投影变化。
3. 小范围求解设备组位置、深度、缩放与相机取景，使核心展示阶段满足期望大小/视觉中心；不破坏设备朝向、文字安全区。
4. 编译出原生轨道与关键帧，支持出画入场、核心展示、出画退场。
5. 在 UI 中展示投影框 Debug 开关，能清楚看到目标区域和最终区域。

**验收**：同一语义意图在 16:9 / 9:16 画幅以及不同手机型号下，都形成可理解的构图；出画入场合法且不被强行纠正；经过采样关键帧后不存在明显跳变。

## P2｜多设备组运动与动态布局

**目标**：2–5 台设备能协同入场、展开、错层和退出，整体位置适中、间距可控。

**实现任务**：

1. 新增设备组 `groupTransform(t)` 与设备局部 `localTransform_i(t)` 组织关系；将最终变换编译为现有设备轨道，兼容原编辑器。
2. 单独支持“组整体移动”和“每台设备独立旋转/缩放/分散”两个层级。
3. 实现少量可变布局种子：双手机紧凑并列、三机主次错层、五机展开、手机 + 平板不等尺寸组合。模板的偏移和角度全部可连续调整。
4. 定义跨时间布局状态（`entrance`, `spread`, `focus`, `exit`），允许不同局部延迟和缓动。
5. 基于**设备组整体投影包围矩形**与单设备投影框计算间距、重叠、画面占比和遮挡；允许有意遮挡、出画和夸张透视。
6. 按若干关键时刻预计算轨迹并采样验证，在明显偏离时提示或小幅优化；避免逐帧校正导致抖动。

**验收**：双手机共同移动时视觉间距稳定；三手机可以中央突出/后方错层；五手机从画面外展开进入合理布局；与文字区合用时不无意遮挡标题。

## P3｜AI 构图意图编译与自然语言微调

**目标**：多模态能力一般的模型也能下达复杂而明确的镜头任务。

**任务**：

1. LLM 输出高层构图目标，不直接要求所有 Three.js 世界坐标。
2. 通过有限 schema 表达 `devices`, `layout`, `motionPhases`, `textRegion`, `keyMoments`；阶段时刻和参数为自由连续值，而不是固定格点。
3. 编译器将高层计划转换成 P1/P2 求解目标和可编辑关键帧。
4. 用户输入“左下角入场，中心停 2 秒，中央手机放大，两侧手机后转”时，仅修改相关镜头参数。
5. 预览采样（静帧或缩略视频）作为可选反馈；视觉模型弱或不可用时，也能通过投影统计正常工作。
6. 输出记录可撤销，用户可在专业模式编辑生成的关键帧。

**验收**：至少 10 条不同自然语言描述可生成不同轨迹；不会固定在几个位置；单独修改旋转或停留时不重置其它编辑状态。

## P4｜源码理解 + 分段方案 + 录屏指导

**目标**：实现产品独特价值，不再依赖用户手工说出全部功能。

**任务**：

1. 安全读取 ZIP / 本地项目目录，隔离敏感文件；不默认执行未知代码。
2. 提取技术栈、路由、页面、按钮操作与功能线索，给出 `Feature` 清单和来源证据。
3. 区分“代码确认”“AI 推断”“用户确认”，所有不能确定的操作路径允许人工修改。
4. 基于功能生成 N 个**独立可编辑片段**，而不是固定三镜头。
5. 为每个片段给出具体的录屏准备、逐步操作、建议时长、停留画面、注意事项。
6. 片段可编辑、删除、重新生成单段、改变优先级，不影响其它段。

**验收**：对至少两个结构不同的真实软件项目（可先选 React 和 Flutter）生成不同且可验证的片段清单；用户能按照录屏步骤拍到对应功能。

## P5｜Dify 风格分页面前端、简洁编辑器、收藏与个人模板

**目标**：用户无需面对专业复杂按钮，能从片段列表一步步完成编辑。

**任务**：

1. 独立工作台、项目片段列表、录屏指导、单片段简洁编辑器、模板中心、整片编辑；页面通过明确的按钮跳转。
2. 使用 `visual/ui/screenshots/` 里的**四张正式参考图**，而非旧版拥挤单页。
3. 片段编辑默认只展示四个操作：替换录屏 / 更换模板 / 修改文字 / 调整镜头；其它参数折叠为“高级编辑”。
4. 用户上传录屏后贴到真实模型；切换模板/设备/构图不丢失录屏和编辑状态。
5. 模板库、持久化收藏、最近使用、“保存为我的模板”；模板结构与用户录屏文件分离。
6. 片段与模板数据持久化，支持重新打开项目继续编辑。
7. P3 自然语言微调作为可选入口，不强行堆满当前页面。

**验收**：截图与设计参考具有一致的结构与信息层级；用户可完成“打开片段→看指导→上传录屏→微调→保存”；切换普通/专业模式数据不丢失；收藏跨页面与刷新生效。

## P6｜整片合成 + 统一视觉风格

**目标**：把已完成的片段合成为可播放 MP4。

**任务**：

1. 先独立渲染每个 Three.js 片段（单帧可重复 / 时间轴同步）。
2. Remotion 接收已输出的镜头文件与 `Composition` 时间线，负责片段排序、过渡、标题与字幕动画、背景音乐和最终输出。
3. 建立轻量 `VideoStyle`：字幕位置和样式、几种过渡规则、全局配色/节奏；无须 LLM 逐帧设计。
4. 转场默认简单：连续操作硬切，功能切换短淡化，品牌收尾渐隐；用户可覆盖。
5. 编码失败有明确报错；在技术允许时可落回 PNG 序列 + FFmpeg。
6. 保持片段独立可修改，修改一个片段后不重新规划所有片段。

**验收**：包含 3 个不同录屏功能片段、字幕和配乐的成片输出正常；没有黑屏、重复帧、异常裁切或明显时间错位。

## P7｜增强项（不是 MVP 阻塞）

- 视觉模型校对画面细节，自动判断美观及字幕遮挡（先观察误报）。
- 自动操作目标软件与自动录屏（明确沙箱、安全和运行依赖）。
- 复杂轨迹自动优化、镜头匹配、自动配音、音节奏匹配。
- 更多授权明确的 iPad/MacBook/Android 平板/手表模型。
- 多 Agent 拆分仅在单模型能力/成本真正构成瓶颈后再进行。

## 开发顺序与可并行工作

- **主线**：P0 → P1 → P2 → P3 → P6 技术验证；完成后形成任意镜头的可靠输出能力。
- **产品线可平行**：P4 功能清单协议 → P5 页面信息架构，最终与 P3 / P6 汇合。
- P5 中模板/收藏可提前做数据和静态界面，但接入真实 3D 渲染需等待 P0。
- 阶段通过条件以真实输出、测试与用户体验为准，不按文件数量计进度。
